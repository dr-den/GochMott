# SCHEMA.md — структура `dict.db`

Готовая SQLite-база офлайн-переводчика. Только чтение, руками не правится: собирается
из JSONL-файлов парсеров скриптом `tools/build_app_db_v5.py`.

Схема **многословарная**: в одну базу кладётся несколько книг, каждая со своим
паспортом в `dicts`. Сейчас это три книги — и пять словарей, потому что у двуязычной
книги каждое направление это отдельный ряд `dicts`:

| `code` | книга | направление | статей |
|---|---|---|---:|
| `maciev1961` | Мациев А. Г. Чеченско-русский словарь, 1961 | ce → ru | 19 075 |
| `math1997_ce` | Умархаджиев, Ахматукаев. Словарь математических терминов, 1997 | ce → ru | 1 005 |
| `math1997_ru` | та же книга | ru → ce | 1 322 |
| `comp2017_ru` | Умархаджиев и др. Словарь компьютерной лексики, 2017 | ru → ce | 525 |
| `comp2017_ce` | та же книга | ce → ru | 573 |

```bash
python tools/build_app_db_v5.py app/src/main/assets/dict.db \
    --dict maciev1961=rawSources/maciev.jsonl \
    --dict math1997_ce=tools/1/math1997_ce.jsonl \
    --dict math1997_ru=tools/1/math1997_ru.jsonl \
    --dict comp2017_ce=tools/1/comp2017_ce.jsonl \
    --dict comp2017_ru=tools/1/comp2017_ru.jsonl \
    --links --links-report tools/1/conflicts.tsv --reviewed tools/reviewed.tsv
```

Ключи поиска считает сам сборщик портами кода приложения: `normalize_ce` ↔
`ChechenNormalizer.kt`, `normalize_ru` ↔ `RuNormalizer.kt`, `fuzzy_ce`/`fuzzy_ru` ↔
`FuzzyKey.kt`, `ru_stem` ↔ `RuStem.kt` (Snowball из Lucene). Флаг `--verify` сверяет
стеммер с эталонным `snowballstemmer`. **Правка любого из четырёх файлов требует
пересборки базы**, иначе точный поиск разойдётся.

## Версия базы — `PRAGMA user_version`

Сейчас **5**. База целиком read-only, пользовательских данных в ней нет, поэтому на
устройстве она не мигрируется, а перезаписывается копией из assets. Признак «пора
перезаписать» — расхождение `PRAGMA user_version` локальной копии с константой
`DatabaseHelper.EXPECTED_DB_VERSION`.

**При каждой пересборке поднимайте оба числа сразу:** `DB_USER_VERSION` в сборщике и
`EXPECTED_DB_VERSION` в коде. Расхождение ловит `DbVersionTest`.

| версия | что изменилось |
|---:|---|
| 5 | `glosses.gram`, `lemma_links.reviewed` / `note`; в базе словари 1997 и 2017 |
| 4 | многословарная раскладка: `dicts`, `lemma_links`, `label_uses`; `word_forms`→`forms`, `ru_index`→`trans_index`, `glosses.ru`→`glosses.text`; везде `dict_id` и `lang` |
| 3 | новая база из `maciev.jsonl`: `entries`→`lemmas`, значения разложены на `glosses`, примеры привязаны к значению, добавлены `subs`, `blocks`, `ru_index` на уровне глосса |
| 2 | `ru_index`: `sense_id` → `lemma_id` |
| 1 | первая версия словаря |

Откат — подмена файла `dict.db` и возврат прежнего `EXPECTED_DB_VERSION`: миграции на
устройстве нет, терять нечего.

Копить изменения внутри ещё не выпущенной версии правильно: номер существует, чтобы
поймать расхождение между базой и кодом, которые УЖЕ стоят у пользователя. Отдельный
бамп нужен ровно тогда, когда предыдущий номер куда-то уехал.

## Роль против языка — главное правило схемы

Таблицы названы по **роли**, а не по языку, потому что в базе есть словари обоих
направлений:

| таблица | роль | язык |
|---|---|---|
| `forms` | сторона **заголовка** | `lang` = `dicts.lang_src` |
| `glosses` | сторона **перевода** | `lang` = `dicts.lang_tgt` |
| `trans_index` | обратный индекс по стороне перевода | `lang` = `dicts.lang_tgt` |

У словаря чеч→рус заголовки чеченские, переводы русские; у словаря рус→чеч —
наоборот. Поэтому одно и то же слово живёт в двух местах: `хаамаш` — заголовок
в книге 2017 (чеч→рус) и перевод в ней же (рус→чеч, статья `да́нные`).

**Из этого не следует, что искать надо всюду.** Строка `trans_index` с `lang='ce'`
принадлежит статье с РУССКИМ заголовком, и в выдаче «чеченский → русский» она
отвечает на обратный вопрос. Какие слои опрашивает каждое направление —
в `StructNote.md`, раздел «Почему направления несимметричны».

**Из этого же следует правило для UI:** сторону нельзя угадывать по месту в карточке.
У статьи `ада́птер` (2017, рус→чеч) ударение стоит в ЗАГОЛОВКЕ, а долгота — в переводе
`чIа̃на`; у `ма̃ша` наоборот. Поэтому каждая строка приходит со своим `lang`, а знак
выбирает `Marks.forLang`. По тому же признаку разворачивается порядок сторон в
примерах: `examples.ru` у книги рус→чеч это заголовочная сторона, а не перевод.

Исключение — `examples.ce` / `examples.ru`: они названы **по языку**, а не по роли, и
верны в обе стороны. В словаре рус→чеч `ru` это русское сочетание, `ce` — его
чеченский перевод.

## Диакритика: что где лежит

```
чеченский   headword / form / ce      «ха̃дадала»    СО чёрточкой долготы -> в UI
            headword_norm / *_norm    «хададала»    ключ точного поиска
            headword_fold / *_fold    «хададала»    скелет примерного поиска
русский     text / ru                 «ка́ждый раз»  СО ударением -> в UI
            text_norm / ru_norm       «каждый раз»  ключ поиска
            text_fold / ru_fold       «кождыйроз»   скелет фразы
```

Оба языка хранятся **размеченными**, потому что снять знак — один проход по строке,
а поставить обратно — нельзя без позиций. Массивов позиций в базе нет: они не нужны.
Снятием занимается `Marks` (`ui/Marks.kt`) прямо при отрисовке — репозиторий отдаёт
текст как есть. Флаги там Compose-состояние, поэтому переключатели в боковом меню
перерисовывают уже открытую статью без повторного запроса к словарю; сами значения
хранит `DisplayPrefs` рядом с остальными настройками. По умолчанию показаны оба.

В буфер обмена по долгому тапу уходит текст **без обоих знаков**, независимо от
переключателей: скопированное вставляют в поиск или в переписку, где комбинирующие
U+0303 и U+0301 не совпадут ни с чем. Чистка — `Diacritics.plain` (`search/Diacritics.kt`),
там же лежат сами константы знаков.

## Модель

```
dict ─< lemma ─┬─< form                      ключи прямого поиска (сторона заголовка)
               ├─< lemma_class               классы в/й/д/б, раздельно ед./мн.
               ├─< block ─< sense            блок части речи (не у всех статей)
               ├─< sense ─┬─< gloss          перевод; их несколько на значение
               │          └─< example ─< sub пример значения и его подпункты
               ├─< example (is_idiom=1)      идиомы за «◊» — у статьи, не у значения
               ├─< cross_ref                 «понуд. от», «см.», «прил. к» …
               └─< trans_index -> gloss | example   обратный поиск

lemma >──< lemma  через lemma_links          то же слово в другой книге
```

## Паспорта источников

### `dicts` — один ряд = один словарь одного направления
`id, code, book, title, authors, year, place, publisher, lang_src, lang_tgt,
priority, n_lemmas, citation`.

`code` — то, что подаётся сборщику (`maciev1961`). `book` общий у двух направлений
одной двуязычной книги: тогда в таблице два ряда с разными `lang_src`.

`priority` — паспортный порядок показа книг в выдаче: **первый ключ сортировки после
точности совпадения**. `citation` — готовая строка для подписи под статьёй и для
«поделиться», склеивать её в UI не нужно.

### `lemma_links` — то же слово в другой книге
`id, a_lemma_id, b_lemma_id, a_dict_id, b_dict_id, lang, method, confidence, conflict`.

`id, a_lemma_id, b_lemma_id, a_dict_id, b_dict_id, lang, method, confidence, conflict,
reviewed, note`.

`method` ∈ `norm | class | fold+gloss | manual` (769 / 28 / 15 / 0). **Поля книг не
сливаются никогда:** связь говорит лишь «это одно слово». `conflict` — JSON-массив
полей, в которых книги расходятся (класс, часть речи). Непустой `conflict` не ошибка
сборки, а разночтение источников: показываем оба варианта с указанием книги, а не
выбираем победителя.

`reviewed = 1` — пару смотрел человек и записал решение в `tools/reviewed.tsv`;
`note` — его же объяснение. Для UI это значит: тревожную плашку «книги расходятся»
показывать не нужно, вместо неё идёт `note`. Сам класс всё равно берётся от обеих
книг — подтверждение говорит «обе правы», а не «выбран победитель».

Пара хранится один раз и без направления, поэтому «другая» статья — та сторона,
которая не равна нашей (см. `DictRepository.getRelated`).

## Справочники

**`pos`** (id, code, name_ru, ordering) — 15 частей речи кодами Мациева:
`сущ, прил, гл, масд, прич, деепр, нареч, числ, мест, послелог, союз, частица,
межд, звукоподр, приставка`.

**`case_type`** (id, code, name_ru, abbr_ru, ordering) — `nom, gen, dat, erg, all,
instr, cmp, subst`. Реально в словаре встречаются первые пять.

**`number_type`** (id, code, name_ru) — `sg`, `pl`.

**`verb_tam`** (id, code, name_ru, ordering) — `inf, masd, pres, past_wit, perf,
imperf, fut, imp, cvb, ptcp`. В данных: `pres`, `past_wit`, `perf`, `fut`.

**`labels`** (id, code, n_uses) — 99 помет словаря; коды общие для всех книг,
частоты пословарно лежат в **`label_uses`** (dict_id, label_id, n_uses).
**Расшифровывать не нужно**: у Мациева это уже читаемые сокращения («перен.», «бот.»,
«уст.»), их и показываем. В `lemmas`/`senses`/`glosses`/`examples` пометы лежат
JSON-массивами кодов.

**`meta`** (key, value) — версия схемы, список источников (`sources`), чеченский
стоп-лист (`ce_stopwords` — 40 самых частотных токенов переводов, взяты из данных,
а не выдуманы), было ли собрано FTS5.

## Ядро

`dict_id` есть на `lemmas`, `forms`, `senses`, `glosses`, `examples`, `subs`,
`cross_refs`, `trans_index`, `blocks`, `lemma_class`. Денормализовано намеренно:
иначе фильтр по источнику потребует джойна и покрывающий индекс перестанет покрывать.

### `lemmas` — статья
| колонка | смысл |
|---|---|
| `id` | INTEGER PK |
| `dict_id` | из какой книги статья |
| `lang` | язык заголовка, дубль `dicts.lang_src` |
| `slug` | исходный id статьи из JSONL (`мохь-2`), уникален в паре с `dict_id` |
| `headword` | заголовок со знаками долготы |
| `headword_norm` | ключ точного поиска |
| `headword_fold` | скелет примерного поиска; читается прямо в `FuzzyIndex` |
| `homonym` | номер омонима или **NULL** (в модели → `homographN = 0`) |
| `pos_id` | первая часть речи; полный список — `lemma_pos` |
| `class_star` | 1 = глагол меняется не только по классу `д`, но и по б/в/й |
| `pluralia_tantum` | 1 = «только мн.» |
| `cls_sg`, `cls_pl` | классы JSON-массивами (дублируют `lemma_class` для удобства) |
| `obj_num`, `subj_num` | `sg`/`pl` — пометы «объект в ед.», «субъект во мн.» |
| `gram` | JSON про сторону заголовка. **Сейчас это НЕ грамматика из книги:** у 295 статей 1997 года лежит `{"stem": "абсцисс"}` — выведенная основа, показывать её нельзя. Русская грамматика Карасаева (`gender`, `aspect`, `forms`) ляжет сюда же, когда появится |
| `labels`, `flags` | JSON-массивы |
| `src_ref` | номер абзаца в исходнике |
| `richness` | **выведенная** мера подробности статьи — только для сортировки |
| `ordering` | порядок статьи **внутри своей книги**, он же алфавитный |

`indeclinable` отдельной колонкой нет: «нескл.» — обычная помета в `labels`.

> **`richness` в книге не написан — показывать его нельзя.** Это значения + глоссы +
> 2×примеры + напечатанные формы парадигмы. Нужен ровно затем, чтобы при равном
> совпадении полная статья Мациева стояла выше голого «термин → термин» из
> отраслевого словаря.

> **`ordering` больше не глобален.** Он считается внутри словаря, поэтому сортировать
> по нему без `dicts.priority` перед ним нельзя — выдача из нескольких книг пойдёт
> чересполосицей.

### `forms` — единственный вход прямого поиска (бывш. `word_forms`)
Заголовок, варианты написания, падежная и глагольная парадигма и сгенерированные
классные формы лежат вместе; различаются `kind` ∈ `headword | variant | paradigm | class`.

| колонка | смысл |
|---|---|
| `lang` | язык формы = `dicts.lang_src` |
| `form` | со знаками |
| `form_norm` | **ключ поиска**, по нему индекс `(form_norm, lang)` |
| `form_fold` | скелет |
| `case_id`, `number_id`, `tam_id` | подписи для карточки — джойном на справочники |
| `is_headword` | 1 = словарная форма |
| `source` | `dict` напечатано в книге, `gen` собрано заменой классного показателя, `linked` ключ пришёл из другой книги |
| `donor_dict_id` | чей показатель породил строку |

> **`source <> 'dict'` — только ключи поиска, показывать нельзя.** Замена показателя
> даёт верный ключ, но не всегда принятую орфографию: у `даа` й-класс пишется `яа`,
> а генератор выдаёт `йаа`. Ключ, протянутый из другой книги, формой этой статьи не
> является тем более. В карточке фильтруйте `WHERE source='dict'`, в выдаче опускайте
> такие совпадения вниз (`only_gen`).
>
> Позиция показателя не угадывается. Сборщик берёт её (1) из самого словаря — замена
> даёт существующее заглавное слово, `диса*` → есть `биса`, `виса`, `йиса`; (2) из
> единственности — в слове ровно одно место, где в/й/д/б стоит перед гласной;
> (3) по наследству от базового глагола через отсылку «понуд./потенц. от». Где не
> вышло ни одним способом — 433 статьи — формы не генерируются вовсе.

### `senses` / `glosses` — значение и его переводы
`senses`: `id, dict_id, lemma_id, block_id, block_n, sense_no, ordering, pos_id,
labels, cls_sg, cls_pl, pluralia_tantum`. `sense_no` — номер из книги,
**NULL если значение в статье одно**.

`glosses`: `id, dict_id, sense_id, lemma_id, idx, lang, text, text_norm, text_fold,
sep, note, gov, labels, gram`.

Колонки `ru`/`ru_norm` начиная с v4 называются `text`/`text_norm`: у словаря рус→чеч глосс
чеченский, и имя `ru` было бы враньём прямо в схеме. `text_fold` — новый скелет
фразы, по нему примерный поиск работает и по переводам.

Одно значение = несколько переводов: «ослабле́ние; утомле́ние» — два глосса.
`sep` — разделитель **перед** глоссом: `,` синонимы, `;` более далёкий перевод.
`note` — уточнение в скобках («кисть» у «рука́»), `gov` — управление («чем-л.»).

`gram` (v5) — грамматика САМОГО ПЕРЕВОДА, а не заголовка: `{"cls": ["й", "й"]}` —
классный показатель чеченского слова для ед. и мн. числа, ровно как книга 2017 печатает
его в скобках: `адаптер (й, й)`. Заполнен у 1 226 глоссов словарей рус→чеч; у чеч→рус
класс стоит при заголовке и лежит в `lemma_class`. Это факт из книги — показывать
можно и нужно.

### `examples` / `subs` — примеры и идиомы
`examples`: `id, dict_id, lemma_id, sense_id, is_idiom, idx, ce, ce_norm, ce_fold,
ru, ru_norm, ru_fold, kind, note, note_kind, gov, labels`.
`sense_id` заполнен у примеров значения; у идиом за «◊» он NULL, `is_idiom=1`.
`kind` ∈ `phrase | посл. | погов.`
`note_kind='букв.'` + `note` — буквальный перевод идиомы.

Пустая строка и `NULL` здесь разные значения: `ru = ''` это пример **без перевода**,
их у Мациева семь.

`subs`: разбитый перевод примера — «куьг таӀо: а) кри́кнуть, б) окли́кнуть».
Колонки: `id, dict_id, example_id, idx, letter, lang, text, text_norm, note, gov,
labels` (бывшая `ru` — тоже `text`).

### `cross_refs` — отсылки
`id, dict_id, from_lemma_id, rel, to_headword, to_headword_norm, to_lemma_id, to_homonyms`.
`rel` уже человекочитаем: «понуд. от», «потенц. от», «см.», «прил. к», «мн. от»,
«масд. от», «прич. прош. вр. от» — 15 видов. Если `to_lemma_id` не NULL, ссылка
кликабельна; 41 отсылка из 6 023 ведёт в статью, которой в словаре нет.

Отсылка **не пересекает границу книги** — сборщик это проверяет.

## Поисковые надстройки

### `trans_index` — обратный индекс по стороне перевода (бывш. `ru_index`)

```sql
CREATE TABLE trans_index(
  id        INTEGER PRIMARY KEY,
  dict_id   INTEGER NOT NULL,
  lang      TEXT NOT NULL,   -- язык слова = dicts.lang_tgt
  word      TEXT NOT NULL,   -- нормализованное слово перевода
  stem      TEXT NOT NULL,   -- Snowball (ru) | скелет FuzzyKey (ce)
  lemma_id  INTEGER NOT NULL,
  src       INTEGER NOT NULL, -- 0 глосс, 1 пример, 2 идиома, 3 протянуто по отсылке
  target_id INTEGER           -- glosses.id либо examples.id
);
```

* **Индекс висит на глоссе, а не на статье.** У «утомле́ние» видно, что у `хьахар¹`
  совпало значение 1 из 4, а не статья целиком. Показанный перевод — `matchedGloss`.
* **`src` задаёт вес.** Совпадение в переводе значения (33 813 записей) сильнее, чем
  в примере или словосочетании (37 826) или идиоме (1 313); сортировка идёт по `MIN(src)`.
* **20 515 записей протянуты по отсылкам** (`src=3`). Статьи вида «понуд. от X»
  своих переводов не имеют и иначе по-русски не находятся вовсе.
* **`stem` — одна колонка, но разное содержимое.** Для `lang='ru'` это основа
  Snowball, для `lang='ce'` — скелет `FuzzyKey`. Значит и ключ подавать надо разный:
  `RuStem.stem(w)` либо `FuzzyKey.chechen(w)`.

Служебные слова не индексируются — **но только если в глоссе есть что-то ещё**: у
союза `а` перевод это ровно «и», и выбросить его значило бы потерять статью. Для
русского список фиксированный (`RU_STOPWORDS`), для чеченского готового списка нет,
поэтому берутся 40 самых частотных токенов переводов; список лежит в
`meta.ce_stopwords` (у одного словаря чеч→рус он пуст — чеченской стороны перевода
в базе пока нет).

Фразовый слой отдельной таблицей не нужен: перевод целиком лежит в `glosses.text_norm`,
по нему есть индекс. 82 % переводов однословные, 18 % — фразы.

### `forms_trgm` (FTS5 trigram) — подстрока и опечатки
Внешнее содержимое (`content='forms'`), места почти не занимает сверх индекса.
⚠ Требует FTS5 в системном SQLite — есть не на всех старых Android. Признак —
`DatabaseHelper.hasFts5`, запасной путь `WHERE form_norm LIKE '%'||?||'%'`.
Таблица общая для всех языков, поэтому в запросе нужен ещё и фильтр `f.lang = ?`.

---

## Что важно помнить

- **Прямой и обратный поиск работают на штатном SQLite любого Android.** FTS5 нужна
  только подстрочному пути, и у него есть фолбэк.
- Чеченский ввод нормализуй `ChechenNormalizer.normalize()`, русский —
  `RuNormalizer.normalize()`. **Разными объектами:** `ChechenNormalizer` превращает
  `1`, `i`, `l`, `|` в палочку — это способ набрать `Ӏ` с обычной раскладки, и «1-й
  ряд» через него станет «Ӏ-й ряд».
- Язык запроса не угадывается: направление задаёт UI, и ключ идёт в ветку своего
  языка. Пустая ветка просто ничего не возвращает.
- Палочка везде в каноническом `Ӏ` U+04C0. Строчная `ӏ` U+04CF в ключи не попадает —
  сборщик это проверяет и падает, если найдёт.
- Сторона (какой язык где) определяется по `lang`, а не по месту в карточке: в базе
  есть словари обоих направлений. То же и в примерах — `examples.ru` у книги рус→чеч
  это заголовочная сторона.
- **Вводных частей книг в базе нет** — предисловия и правила построения лежат
  в `assets/about.json` и `assets/books/*.json`, список книг в `assets/books/index.json`
  (собирает `tools/build_books_json.py`). База хранит статьи, а не предисловия.
- 36 статей не находятся по стороне перевода: своих переводов нет, а отсылка ведёт
  в статью, которой в книге нет. Это дырки исходника, не сборки.
- В `examples.ce` осталось 22 строки с латинской `I` вместо палочки. Поиск это не
  ломает (`ChechenNormalizer` переводит её в `Ӏ`), но в карточке видна чужая буква —
  чинить надо в парсере, см. `tools/find_homoglyphs.py`.
