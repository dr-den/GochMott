# Выпуск релиза

Приложение выходит в четырёх маркетах и на GitHub. Везде — **одна и та же сборка**
одного и того же кода, разных вариантов приложения не существует.

| Куда | Формат | Откуда взять |
|---|---|---|
| Google Play | AAB | артефакт `aab-<тег>` во вкладке Actions |
| Xiaomi GetApps | AAB | тот же артефакт |
| Samsung Galaxy Store | AAB | тот же артефакт |
| Huawei AppGallery | AAB | тот же артефакт |
| GitHub Release | APK | прикрепляется к релизу автоматически |

APK — универсальный (все экраны и оба языка внутри), нужен только чтобы человек мог
скачать файл и поставить вручную. В маркеты его заливать не нужно.

## Как выпустить

1. Поднять `versionCode` и `versionName` в `app/build.gradle.kts`.
   `versionCode` должен расти при каждой публикации и быть **одинаковым во всех маркетах**.
2. Закоммитить, поставить тег и отправить его:
   ```
   git tag v1.0.5
   git push origin v1.0.5
   ```
   Тег `v*` — обычный релиз, тег `b*` (например `b7`) — pre-release для тестов.
3. Дождаться workflow «Build and Publish Release». Он соберёт подписанные AAB и APK,
   проверит, что подпись не отладочная, создаст GitHub Release с APK и контрольными суммами.
4. Скачать из Actions артефакты `aab-<тег>` и `mapping-<тег>` и залить AAB в кабинеты маркетов.

`mapping.txt` нужен, чтобы читать стектрейсы из отчётов о падениях: сборка обфусцирована.
В AAB для Google Play маппинг уходит сам, для остальных маркетов файл заливается отдельно
(или хранится у себя — артефакт живёт 90 дней).

## Словарная база

`app/src/main/assets/dict.db` в git не хранится: она весит больше сотни мегабайт,
а GitHub не принимает файлы тяжелее ста. В репозитории лежат её исходники —
`rawSources/work/*.jsonl` и сборщик `tools/db_builders/build_app_db.py`, — а сама
база собирается задачей `:app:buildDictDb`. Задача висит на `preBuild`, так что
отдельно её звать не нужно.

Пересборка идёт только когда менялись jsonl или сборщик: задача сравнивает
отпечаток входов с сохранённым в `.dictdb-stamp` и пропускается, если он совпал.
Отпечаток по содержимому, а не по датам файлов, — git при клоне ставит всем файлам
время выгрузки, и по датам база пересобиралась бы на каждой чистой машине.

Нужен Python 3. Если он зовётся не `python3` и не `python`, укажите его явно:

```
./gradlew assembleDebug -PpythonExecutable=C:\Python312\python.exe
```

Сборка базы занимает около получаса. В CI результат кэшируется по хэшу тех же
входов, поэтому полчаса случаются один раз на изменение данных, а не на каждый
релиз. На чистой машине первая сборка приложения тоже будет долгой — это ожидаемо.

## Секреты репозитория

Workflow ждёт четыре секрета: `KEYSTORE_BASE64` (keystore в base64), `STORE_PASSWORD`,
`KEY_ALIAS`, `KEY_PASSWORD`. Без них сборка падает сразу, а не выпускает debug-подписанный файл.

Локально релиз собирается так же — через переменные окружения `KEYSTORE_PATH`,
`KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`. Если их нет, релиз подписывается
отладочным ключом (годится только чтобы посмотреть сборку на своём телефоне).

## Про подписи — важно

Google Play обязательно пересобирает и **переподписывает** приложение своим ключом
(Play App Signing). Все остальные маркеты и GitHub раздают файл с вашей подписью.
Из-за этого подписи различаются, и обновить приложение «поверх» между Play и остальными
источниками нельзя — пользователю придётся удалить старую установку.

Отсюда два правила:

- Один и тот же keystore для GetApps, Galaxy Store, AppGallery и GitHub — иначе они
  тоже перестанут обновляться друг поверх друга.
- Keystore и пароли хранить в надёжном месте. Потеря ключа = потеря возможности
  обновлять приложение везде, кроме Google Play.

## Что просят маркеты

Общее для всех: иконка 512×512, скриншоты телефона, описание, возрастной рейтинг,
ссылка на политику конфиденциальности —
https://dr-den.github.io/GochMott/privacy-policy.html (исходник — `docs/privacy-policy.html`).

- **Google Play** — принимает только AAB. Анкета Data safety: приложение работает
  офлайн и не собирает данные, кроме писем обратной связи, которые пользователь
  отправляет сам.
- **Huawei AppGallery** — требует, чтобы приложение работало на устройствах без сервисов
  Google. Зависимостей от Google Play Services в проекте нет, проверять при добавлении
  новых библиотек.
- **Samsung Galaxy Store** — публикация через Seller Portal, AAB принимает.
- **Xiaomi GetApps** — исторически работает с APK, приём AAB зависит от кабинета и региона.
  Если консоль не принимает `.aab`, заливать APK из GitHub Release: он собран из того же
  коммита и подписан тем же ключом.

## Почему нет ABI-сплитов

Нативного кода в приложении почти нет: единственная `.so` — `libandroidx.graphics.path`
из Compose, все четыре архитектуры вместе весят ~37 КБ при размере APK около 16 МБ.
Раздельные APK под arm64/armeabi/x86 сэкономили бы доли процента, но дали бы пять
почти одинаковых файлов в релизе и вопросы «а какой из них качать».
Поэтому собирается один универсальный APK.
